Study notes

Three lists that only let you touch their ends.

A stack is LIFO (Last In, First Out). A queue is FIFO (First In, First Out). A deque does both.

Each one sits on a plain array here. Working only at the ends keeps every operation at O(1) time.

Words to know

LIFO
Last In, First Out. The last element you add is the first one out. Think of a pile of plates: you add to the top and take from the top. Stacks are LIFO.
FIFO
First In, First Out. Elements leave in the order they arrived, like a checkout line where the first person in line gets served first. Queues are FIFO.
stack
a LIFO list. push(x) adds on top, pop() removes the top, top() (or peek) looks at it without removing it.
queue
a FIFO list. enqueue(x) joins at the rear, dequeue() leaves from the front, first() looks at the front.
deque
“double-ended queue”, said “deck”. You can add and remove at both ends, so it works as a stack or as a queue.
overflow
adding to a structure that is already full (here, all 8 array slots are in use).
underflow
removing from (or looking into) an empty structure.

Queues only: why a circular array?

Stacks don't need one. A stack's bottom stays at index 0 forever.

A queue is different. It removes from the front, so the front keeps moving. You can handle that three ways:

Array queue strategyenqueuedequeueproblem
front pinned at index 0O(1)O(n)every dequeue shifts n − 1 elements
front index moves, no wrapO(1)O(1)freed slots are never reused: “full” with empty space
circular (front + size, mod N)O(1)O(1)none. Every slot is reusable.

Times are worst case, and all three use O(1) extra space.

The circular array lets the front index wrap from N − 1 back to 0. Tracking size alongside front is how you tell a full queue from an empty one.
