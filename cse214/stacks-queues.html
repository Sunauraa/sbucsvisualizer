Stacks, Queues & Deques

Three lists that only let you work at their ends. A stack is LIFO (Last In, First Out), a queue is FIFO (First In, First Out), and a deque allows both. Each one is built on a plain array here, and limiting access to the ends is what makes every operation O(1) time.

Words to know

LIFO
Last In, First Out. The element added most recently is the first one removed. A pile of plates: you put plates on top and take them off the top. Stacks are LIFO.
FIFO
First In, First Out. Elements leave in the order they arrived. A line at a checkout: the first person in line is served first. Queues are FIFO.
stack
a LIFO list. push(x) adds on top, pop() removes the top, top() (or peek) looks at it without removing it.
queue
a FIFO list. enqueue(x) joins at the rear, dequeue() leaves from the front, first() looks at the front.
deque
“double-ended queue”, said “deck”. Add and remove at both ends, so it can be used as a stack or as a queue.
overflow
adding to a structure that is already full (here, all 8 array slots are used).
underflow
removing from (or looking into) an empty structure.

Queues only: why a circular array?

Stacks don't need this, because a stack's bottom stays at index 0 forever. A queue removes from the front, so the front keeps moving. There are three ways to handle that:

Array queue strategyenqueuedequeueproblem
front pinned at index 0O(1)O(n)every dequeue shifts n − 1 elements
front index moves, no wrapO(1)O(1)freed slots are never reused: “full” with empty space
circular (front + size, mod N)O(1)O(1)none. Every slot is reusable.

(time, worst case; all three use O(1) extra space.) The circular array lets the front index wrap from N − 1 back to 0. Tracking size as well as front tells a full queue apart from an empty one. The Queue: plain vs circular tab runs the versions side by side.
