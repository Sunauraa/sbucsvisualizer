Study notes

Click to build a graph. Drag vertices wherever you like, even mid-traversal.

The adjacency matrix and adjacency list show the same graph two ways, and both highlight in step with the search.

Matrix or list?

Operation (time / extra space)MatrixList
memory for the graphO(V²)O(V + E)
is (u,v) an edge?O(1) / O(1)O(deg u) / O(1)
iterate neighbours of uO(V) / O(1)O(deg u) / O(1)
add edgeO(1) / O(1)O(1) / O(1)
BFS / DFS overallO(V²) / O(V)O(V + E) / O(V)

Real graphs are sparse: E sits closer to V than to V². That's why adjacency lists almost always win.

Load the complete K₆ preset for the exception: every pair of vertices is joined. Dense graphs like that are the only case where the matrix keeps up.

Vocabulary the visualizer uses

degree
edges touching a vertex (in + out if directed)
path / cycle
walk with no repeated vertex / one that returns to its start
connected
every vertex reachable from every other
component
a maximal connected piece (one DFS tree each)
tree edge
the edge that first discovered a vertex
back edge
points to a vertex still on the stack ⇒ a cycle
