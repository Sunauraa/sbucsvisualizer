Study notes

A graph is a map of places and roads. Click to build one and drag places anywhere, even mid-search; the matrix and list beside it are two ways of writing the same map.

The two traversals side by side

BFSDFS

time (worst case)O(V + E)O(V + E)
extra space (worst case)O(V), a whole level in the queueO(V), the deepest path on the stack

Matrix or list?

Operation (time / extra space)MatrixList
memory for the graphO(V²)O(V + E)
is (u,v) an edge?O(1) / O(1)O(deg u) / O(1)
iterate neighbours of uO(V) / O(1)O(deg u) / O(1)
add edgeO(1) / O(1)O(1) / O(1)
BFS / DFS overallO(V²) / O(V)O(V + E) / O(V)

Real graphs are sparse (E is near V, not V²), so lists win. Only dense graphs, like the complete K₆ preset, favour the matrix.

Vocabulary the visualizer uses

degree
edges touching a vertex (in + out if directed)
path / cycle
walk with no repeated vertex / one that returns to its start
connected
every vertex reachable from every other
component
a maximal connected piece (one DFS tree each)
tree edge
the edge that first discovered a vertex
back edge
points to a vertex still on the stack ⇒ a cycle
