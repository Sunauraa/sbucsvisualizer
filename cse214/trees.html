Study notes

A tree is a family tree of smaller family trees, and a search tree is a game of “higher or lower?”. Everything here is about keeping that game short: balanced trees keep every answer O(log n) questions away.

The four rotation cases

Find the lowest unbalanced node; the two steps from it toward the new key pick the rotation:

Casebf(node)bf(child)Fix
Left-Left+2≥ 0single right rotation
Left-Right+2< 0left on child, then right
Right-Right−2≤ 0single left rotation
Right-Left−2> 0right on child, then left

A rotation is an O(1) pointer swap that keeps the order. Insert needs at most one; delete may need one per level.

Overflow, underflow, and why heights match

Multiway trees never rotate: shelves change how many keys they hold, so every leaf stays at the same depth.

overflow
too many keys after an insert → split, middle key goes up
underflow
too few keys after a delete → transfer from a sibling that has spare keys
no spare keys
→ fusion: merge two siblings plus the separator into one node
grows taller
only when the root splits, so all leaves rise together
grows shorter
only when a fusion empties the root

Height: between log₄n and log₂n for a (2,4)-tree; ≤ log⌈m/2⌉n for a B-tree, so 3 levels hold a million keys at m = 100.
