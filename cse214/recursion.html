Study notes

Recursion is solving a problem by handing a smaller copy of it to yourself. Each call is a sticky note on a pile (the stack) that waits for the one above it. Try Iterative to see the same answer from a loop.

Worst case throughout; recursion's space is its stack of waiting frames. When the call is the very last step (tail recursion), a loop does the same in Θ(1) space.

Recursion reads best when a problem branches. Loops save space and can't hit StackOverflowError.

The three things every recursive method needs

1 · A base case

The smallest doll, answered directly. Without it the calls never stop (StackOverflowError).

2 · Progress toward it

Each call gets a strictly smaller input (n−1, n/2, one character shorter), so you reach the base case.

3 · Correct combination

Trust the smaller call to work (the "leap of faith"), then build your answer from it. Induction proves the trust is safe.
