Any recursion can be rewritten as a loop plus a stack, because that is how the machine runs it. When the recursive call is the very last thing a function does (tail recursion, as in gcd), the stack isn't needed and a plain loop does it in O(1) space. Recursion wins on clarity for branching problems (Hanoi, trees, permutations). Iteration wins on space and on not hitting StackOverflowError for deep inputs.

The three things every recursive method needs

1 · A base case

At least one input it can answer without recursing. Miss this and you get infinite recursion, which in Java means StackOverflowError.

2 · Progress toward it

Every recursive call must be on a strictly smaller input — n−1, n/2, one character shorter. Otherwise the base case is never reached.

3 · Correct combination

Assume the recursive call is already correct (the "recursive leap of faith") and just combine its answer properly. That is what induction proves.
